# Modules

## Goal

Add `import`, qualified names, and multi-file programs (willow.md §18). When done,
the §18 example checks, builds, and runs; `check`, `run`, and `build` process every
module reachable from the entry file; errors in any module are reported with that
module's path and prevent execution and output; runtime frames name the file of
each location; and a built program is one standalone Lua file.

## Related code

- `compiler/span.lua` — `span.new(line, col, first, last)`.
- `compiler/lexer.lua` — `M.lex(source)`, `validate`, and `span_at`.
- `compiler/parser.lua` — the file-scope loop, `parse_type`, and the
  unsupported reserved words (`import`).
- `compiler/bind.lua` — `M.bind(program)`, `declarations`, `check_type`,
  `resolve_function`, and the `MethodCall` and `Name` branches.
- `compiler/check.lua` — `M.check(program)`, the `records` map, and the
  constructor result type.
- `compiler/lower.lua` — `M.lower(program)` and `sites`.
- `compiler/emit.lua` — `M.emit(lowered, path)`, function declarations, `Call`
  emission, `__wlo_sites`, and `__wlo_lines`.
- `runtime/core.lua` — `__wlo_path`, `__wlo_where`, and `__wlo_report`.
- `compiler/diag.lua` — `M.format(path, d)`.
- `compiler/cli.lua` — `compile`, the overwrite check, and diagnostic output.
- `tests/run.lua`, `Makefile` — program tests run each `.wlo` from its own
  directory.

## Decisions

### Paths and diagnostics

- `span.new` takes a fifth `path` argument. `lexer.lex(source, path)` gives every
  span it creates that path, including `validate`'s. The program node's span takes
  the path of the `EOF` token. `diag.format(d)` prints `d.span.path`, so every
  diagnostic names its own file. Unit tests may leave the path out.

### Loading

- A new `compiler/loader.lua` has `load(path, source)`. The entry module's name is
  its file name without `.wlo`; every module's path is the entry's directory
  prefix (as written, possibly empty) followed by `name.wlo`. It visits modules
  depth first in import order and appends each the first time it is seen, so the
  list is ordered by first import with the entry first, and a cycle stops at an
  already-seen name. Each module is a program node with `name` and `path` set. A
  module file that cannot be opened is `cannot load module '<name>': <reason>` at
  the import's span.

### Syntax

- `import NAME` lines at the top of a file fill `program.imports` with
  `{ name, span }`. An `import` after a declaration is
  `imports must come before declarations`. `import` leaves the unsupported
  reserved words.
- `parse_type` reads `NAME . NAME` as a qualified record type; its `records`
  entry gets `module` as well as `name` and `span`. Qualified calls and
  constructors already parse as `MethodCall` on a `Name`.

### Binding

- `bind.bind(modules)` takes the module list; `modules[1]` is the entry. Unit
  tests pass `{ program }`.
- **First pass, per module:** a `declarations` table of functions and records, and
  an `imports` table from import name to module. Imports, functions, and records
  share the namespace check already used for functions and records, in source
  order (`duplicate import '<name>'` for a repeated import). Each declaration
  gets `module` set to its program node. Each record gets `type_name`: its name in
  the entry module and `module.name` otherwise, so record types stay nominal
  across files and entry-file messages are unchanged.
- **Second pass:** types and bodies, after every module's declarations exist.
  `resolve_type(type, module)` looks up each `records` entry (qualified through
  the module's `imports`; `unknown module '<name>'`), rejects a `_` name from
  another module (`'<name>' is private to module '<module>'`), and rewrites
  `type.name` by replacing, in order, each identifier that is not a type keyword
  with the resolved record's `type_name`. It replaces `check_type` for fields,
  parameters, returns, and annotations.
- A `MethodCall` whose object is a `Name` that is not a local and names an import
  becomes, in place, a `Call` with `name` set to `module.name` (for messages) and
  `target` set to that module's function or record; a missing name is
  `module '<module>' has no function or record '<name>'`, and a private one is the
  privacy error. A `Name` that names an import is
  `module '<name>' cannot be used as a value`. Locals already shadow module
  names because the scope is consulted first.
- `main` is required only in `modules[1]`.

### Checking

- `check.check(modules)` builds `records` from every module keyed by
  `type_name` and checks every function of every module. A constructor call has
  the record's `type_name`.

### Lowering and emission

- `lower.lower(modules)` lowers every function of every module in module order;
  lowered functions keep their `module`. Sites stay one shared list.
- Functions of the entry module stay forward-declared Lua locals. Each other
  module gets a table `__wlo_module_<name>` declared with them, and its functions
  are defined as `function __wlo_module_<name>.<mangled>(...)`. The prefix keeps
  module tables apart from runtime helpers and user names. A call to a function
  in another module goes through that module's table. When some module imports
  the entry module, the entry also gets a table, filled after the definitions
  (`__wlo_module_main.helper = helper`), and calls from other modules use it,
  so a local in the calling function cannot shadow the entry function.
- `emit.emit(lowered)` takes the path from spans. It numbers paths in order of
  first use and emits `local __wlo_paths = { ... }`. Site entries become
  `{line, col, path_index}` and line entries `{line, col, path_index, "function"}`;
  `__wlo_where` reads `__wlo_paths[location[3]]` and `__wlo_report` reads the
  function name from index 4.

### CLI

- `compile` calls `loader.load(path, source)` and passes the modules through
  every pass. After a successful compile, `build` rejects an output that is the
  same file as any other module: `error: output <output> is the module file
  <path>`. The early entry-file check stays as it is.
- Diagnostics are formatted with `diag.format(d)`.

## Test plan

- `tests/unit/lexer_test.lua`: spans carry the path given to `lex`.
- `tests/unit/parser_test.lua`: imports parse at the top; an import after a
  declaration and `import a.b` are rejected; `geometry.Point` and
  `list[geometry.Point] | None` as types.
- `tests/unit/bind_test.lua`, with a helper that parses named sources into a
  module list: qualified calls and constructors resolve to the other module's
  declarations; record types in both modules canonicalize to the same string;
  an import conflicting with a function, a record, another import, and a
  built-in; an unknown module in a type; a missing name in a module; private
  functions and records from another module rejected and allowed within their
  own; a module name used as a value; a local shadowing a module name; `main`
  not required outside the entry.
- `tests/unit/check_test.lua`: a record from another module is assignable only
  to the same record; field access on it works.
- Update the pass call sites in `bind_test`, `check_test`, `lower_test`, and
  `emit_test` to pass `{ program }`, and `emit_test` to give `lex` a path.
- Multi-file program tests in `tests/modules/<case>/`, each run as `main.wlo`
  from its directory with `main.out` and `main.err`; `make test` adds
  `tests/modules/*/main.wlo`:
  - `geometry`: the §18 example.
  - `cycle`: modules importing each other and the entry, mutual recursion across
    files, records passed between modules, a private helper used inside its
    module, a non-entry function named `main`, and an entry function called from
    another module whose caller has a local of the same name.
  - `imported_error`: a type error in an imported module, reported with that
    module's path.
  - `missing_module`: an import of a file that does not exist.
  - `runtime_frames`: a runtime failure in an imported module, with frames naming
    both files.
- `tests/unit/cli_test.lua`: a multi-module program built and run from another
  directory matches `run`; `build -o geometry.wlo` with an imported
  `geometry.wlo` is rejected and leaves the file intact.
