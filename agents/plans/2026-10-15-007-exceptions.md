# Exceptions

## Goal

Add exception classes, `raise`, and `try`/`except`/`finally` (willow.md §19), and
turn the runtime failures of earlier slices into catchable built-in exceptions.
When done, the §19 example checks, builds, and runs with the output in its
comments; an uncaught exception reports `file:line:col: error: Class: message`
with the frames recorded at the raise; and host failures (stack exhaustion,
memory exhaustion, output failures) still terminate in the §10 form without
running `finally` clauses.

- `compiler/bind.lua` — `builtins`, `collect_symbols`, `resolve_type`/`lookup`,

- `compiler/emit.lua` — `statement`, `loop_body`, `Construct`, and per-function

## Decisions

- **Exception classes are records.** `class Name(Exception):` parses to a
  `Record` with `exception = true`. The parser accepts exactly one base name,
  which must be `Exception` (`the base of a class must be 'Exception'`), prepends
  a synthetic `message: str` `FieldDecl` (span of the class name), rejects a
  declared `message` (`exception class cannot declare field 'message'`), and
  accepts a body of `pass` alone. Plain records keep their current body rules.
  Everything else (constructors, fields, `type_name`, module qualification)
  reuses the §16 path.
- **Built-in classes.** `bind.lua` builds one shared `Record` per built-in class
  (`Exception`, `OverflowError`, `ZeroDivisionError`, `ValueError`,
  `IndexError`, `KeyError`, `RuntimeError`) with `exception = true`,
  `type_name = name`, and one `message: str` field, and exports them as
  `M.exceptions`. Calls, types, and `except` clauses fall back to them after the
  module's declarations. A file-level declaration with one of these names is
  `cannot redefine built-in class '<name>'`; used as a value it is
  `record '<name>' cannot be used as a value`, as for user records.
- **Types.** An exception type is its record's `type_name`. `check.lua` keeps a
  set `exception_classes` of every exception `type_name` (including
  `Exception`), filled in `M.check`. `assignable(target, source)` also accepts
  `target == "Exception"` with `source` in the set, and for an optional target
  compares the bases, so `ParseError | None` is assignable to
  `Exception | None`. Collections stay invariant because `assignable` compares
  their type strings for equality.
- **Narrowing on assignment.** `assign` now records the base of an optional
  declared type, or the declared type, instead of the value's type, so assigning
  a `ParseError` to an `Exception` local never makes `.line` readable. For
  every earlier type the result is unchanged.
- **Syntax.** `Raise { value }` with `value` nil for bare `raise`; `raise x from y`
  is `'raise ... from' is not supported`. `Try { body, handlers, finally_body }`;
  each handler is `{ class = { name, module, span }, name, body, span }` where
  `name` is the `as` name. Rejections: `except:` is `bare 'except' is not
  supported`, `except (` is `exception class lists are not supported`,
  `except*` is `'except*' is not supported`, `else` after the clauses is
  `'else' clause on 'try' is not supported`, and a `try` with neither clause is
  `expected 'except' or 'finally'`. `as`, `except`, `finally`, `raise`, and
  `try` leave `unsupported`.
- **Binding.** `collect_symbols` and `assigned_symbols` walk `Try` bodies,
  handlers, and `finally`, and treat each `as` name as an assigned name. An
  `except` class resolves like a type name (locals never shadow it) through a
  `resolve_record(ref, module)` factored out of `resolve_type`, then must be an
  exception class (`'<name>' is not an exception class`); `handler.record` holds
  the class. `resolve_block` threads the innermost `Try` whose `except` clause
  encloses the statement; a bare `raise` records it as `statement.try`, and
  without one it is `bare 'raise' is only allowed in an 'except' clause`.
- **Checking.**
  - `raise x` requires `x`'s type in `exception_classes`
    (`expected an exception, received <type>`). `raise` returns true (transfers).
  - A clause after `except Exception`, or naming a class already named, is
    `unreachable 'except' clause` at the clause.
  - The `as` local gets the clause's class as its type when it has none, and
    otherwise the class must be assignable to its type; it is then assigned with
    `assign` inside the clause.
  - Flow per §19: handler entry is the pre-`try` state with narrowing forgotten
    for the body's assigned symbols; `finally` entry additionally forgets the
    handlers' symbols. After the `try`, the falling-through body and handler
    states join; when there is a `finally`, the result takes the `finally` exit
    type for symbols the `finally` assigns or narrows (its type differs from the
    declared type) and keeps the joined type otherwise. The `try` transfers when
    the body and every handler transfer, or when `finally` transfers.
    `forget_loop_narrowing` becomes `forget_narrowing(state, statements)`.
  - `return`/`break`/`continue` in `finally`: a function-level `finally_depth`
    counts enclosing `finally` clauses, and `in_loop` becomes the
    `finally_depth` at the innermost loop (or false). `return` with
    `finally_depth > 0`, and `break`/`continue` with `in_loop < finally_depth`,
    are `'<word>' cannot leave a 'finally' clause`.
- **Runtime values.** An exception is its record table plus `__wlo_class` (the
  class `type_name` string), and, once raised, `__wlo_location` and
  `__wlo_frames`. Mangling gives user fields a trailing `_` for these names, so
  they cannot collide. A host failure is a table with `message`,
  `__wlo_location`, and `__wlo_frames` and no `__wlo_class`. Uncaught
  exceptions print the `type_name`, so a class from module `parser` reports as
  `parser.ParseError`, matching Python.
- **Runtime helpers** (`runtime/core.lua`):
  - `__wlo_frames()` returns the mapped Willow frames on the stack, innermost
    first (the loop now in `__wlo_report`).
  - `__wlo_raise(exception, site)` records location and frames and raises.
    `__wlo_fail(class, message, site)` builds a built-in exception and calls
    `__wlo_raise`; its callers pass class names per the §19 table.
    `__wlo_reraise(exception)` raises without changing it. `__wlo_write` raises a
    host failure through a new `__wlo_host_fail(message, site)`.
  - `__wlo_catch(err)` is the `xpcall` message handler: a raw VM error becomes a
    host failure with the frames active where it happened.
  - `__wlo_try(body)` runs `body` under `xpcall(body, __wlo_catch)`. On success
    it returns what `body` returned (a departure code and value, or nothing);
    a host failure is re-raised at once; an exception returns `"raise"` and the
    exception.
  - `__wlo_run` uses `__wlo_catch` and `__wlo_report(err)` formats the recorded
    location and frames, with `Class: ` before the message for exceptions.
- **Lowering.** A protected block (the `try` body and every `except` body) is a
  closure, so its departures are returned as codes: `return` → `"return"` and
  the value, `break` → `"break"`, `continue` → `"continue"`. Lower keeps a stack
  `tries` of the `Try` nodes whose protected blocks enclose the current
  statement; a `Return` with `#tries > 0`, or a `Break`/`Continue` with
  `#tries > loop.tries` (the stack size when the loop began), gets `exits = true`
  and marks each crossed `Try` with `returns`, `breaks`, or `continues`. After
  the `try`, lower builds the resume statements for the marked codes as ordinary
  `Return { value = TryValue }`, `Break`, and `Continue` nodes in the `try`'s
  own context, so they in turn exit an enclosing closure when needed. A
  protected block lowers with its own `temps` count, declared inside the
  closure, so it does not capture the function's temporaries. Every `Continue`
  sets `loop.continues`.
  - The `Try` node is `{ index, body = { body, temps }, handlers = { { class,
    target, body = { body, temps } } }, finally_body, resume }`; `class` is nil
    for `Exception`, `target` is the `as` local. `index` comes from the
    function's `labels` counter and is recorded by `Try` AST node, so a bare
    `raise` lowers to `Eval(Helper reraise { TryValue(index) })`.
  - `raise x` lowers to `Eval(Helper raise { operand })`, so it has a site and a
    mapped line. An exception constructor's `Construct` carries
    `class = type_name`.
- **Emission.** A `Try` emits:

  ```lua
  do
    local __wlo_code1, __wlo_value1 = __wlo_try(function()
      local __wlo_t1
      -- body
    end)
    if __wlo_code1 == "raise" then
      if __wlo_value1.__wlo_class == "ParseError" then
        error_ = __wlo_value1
        __wlo_code1, __wlo_value1 = __wlo_try(function()
          -- handler
        end)
      else -- the Exception clause, when present
      end
    end
    -- finally statements
    if __wlo_code1 == "raise" then __wlo_reraise(__wlo_value1) end
    if __wlo_code1 == "return" then return __wlo_value1 end
  end
  ```

  The handler's closure reads `__wlo_valueN` for a bare `raise` while the
  handler runs, before the result is assigned. Lines without a Willow call carry
  no span, so the enclosing function's `__wlo_try` call line drops out of
  frames and the closure lines map to the enclosing function's name. A `Return`
  with `exits` emits `return "return", value`; a `Break` or `Continue` with
  `exits` emits `return "break"` or `return "continue"`. `TryValue` emits
  `__wlo_valueN`. `Construct` with `class` emits `__wlo_class = "<name>"` first.

## Test plan

- `tests/unit/parser_test.lua`: `try` with `except`, `except mod.C as e`,
  several clauses, `finally`, and `try`/`finally`; `raise x` and bare `raise`;
  exception class with fields and with `pass`; each rejection listed under
  Syntax, a non-`Exception` base, and a declared `message` field.
- `tests/unit/bind_test.lua`: redefining `ValueError`; `except` naming an
  unknown name, a function, and a plain record; bare `raise` outside `except`,
  inside an `if` in an `except`, and inside a nested `try` body within an
  `except`; `Exception` and `mod.Error` in annotations; a local shadowing an
  exception constructor.
- `tests/unit/check_test.lua`: constructor arity counting `message`; field reads
  of `message` and declared fields; `ParseError` assignable to `Exception` and
  `Exception | None` but `list[ParseError]` not to `list[Exception]`; reading
  `.line` from an `Exception` local assigned a `ParseError` rejected; `raise` of
  an `int` and of an unnarrowed optional; unreachable clauses; `return`, `break`,
  and `continue` in `finally` rejected while a loop inside `finally` may break;
  missing return satisfied by `raise` and by a `try` whose body and handlers
  return; unreachable statement after such a `try`; a local assigned in the body
  not definite in `except` or `finally` but definite after when every clause
  assigns it; narrowing kept into `except` only for locals the body does not
  assign; `as` typing fixing and checking the local type.
- `tests/programs/exceptions.wlo` with `.out`: the §19 example; catching each
  built-in class from its runtime failure; clause order and `except Exception`;
  propagation through calls; `finally` on fall-through, `return` (value
  evaluated first), `break`, `continue`, and exceptions; an exception in
  `finally` replacing one in flight; a `try` inside a loop inside a `try`;
  nested `try` in a handler with bare `raise`. Expected output from running the
  program under Python with `@dataclass` exception classes adapted to positional
  `message`.
- `tests/programs/uncaught_exception.wlo` with `.err`: a user exception raised
  two calls deep, caught, and re-raised with bare `raise`, reporting the
  original location and frames.
- `tests/modules/exceptions/`: an exception class in an imported module raised
  there, caught in `main` with `except errors.ParseError as e`, and an uncaught
  one reporting `errors.ParseError: ...` with frames in both files.
- Existing `.err` expectations gain class names; host failure tests in
  `emit_test.lua` stay as they are.
