# Lower

## Goal

Replace the `compiler/lower.lua` stub with the pass that makes Willow's
evaluation rules explicit before emission (willow.md §5 and §9).
`lower.lower(program)` turns the checked tree into a lowered program that the
emitter can print almost line for line:

- operands and arguments run left to right, with calls and integer helpers held
  in temporaries;
- `and` and `or` short-circuit through branches;
- integer `+ - *` and negation become helper calls carrying a site ID;
- `print` becomes a helper call;
- a returned call goes through a temporary;
- `while`, `break`, and `continue` use labeled loop transfers.

Every generated statement holds at most one call. `willow run` still stops at
the emit stub after this change.

## Related code

- `compiler/lower.lua` — stub to replace; keeps `M.lower(program)`.
- `compiler/check.lua` — sets `node.type` on every expression (`"int"`, `"bool"`,
  `"str"`, `"None"`); lowering reads it to tell integer `+` from string `+`.
- `compiler/bind.lua` — `Assign.symbol`, `Name.symbol`, `Param.symbol`,
  `Function.locals`, and `Call.target` (a `Function` node or the built-in
  `{ kind = "Builtin", name = "print" }`).
- `compiler/parser.lua` — node shapes; `elif` is a nested `If`; `Binary` and
  `Unary` spans are the operator and `Call` spans the name.
- `compiler/cli.lua` — already calls `emit.emit(lower.lower(program), path)`.

## Decisions

- **Lowered program.** `lower.lower(program)` returns `{ functions, sites }`.
  - Each entry in `functions` is
    `{ name, span, params, locals, temps, body }`. `params` and `locals` are
    bind's symbols, and `temps` is the number of temporaries the function needs.
  - `sites[id]` is the span of the operation whose helper call carries `id`.
    Site IDs count from 1 across the program in lowering order, so output is
    deterministic.
- **Lowered expressions** never contain calls except at the top of a value:
  - `Literal { value }`: a number, string, boolean, or nil for `None`.
  - `Local { symbol }` and `Temp { index }`.
  - `Not { operand }` and `Binary { op, left, right }`, where `op` is one of
    `== != < <= > >= and or concat`. `concat` is string `+`.
  - `Call { target, args }`, with `target` the `Function` node.
  - `Helper { name, args, site }`, with `name` one of `add sub mul neg print`.
- **Lowered statements.** Each carries the `span` the source map will use: the
  call or operator span for a statement whose value is a `Call` or `Helper`,
  otherwise the source statement's span.
  - `Set { target, value }`, where `target` is a `Local` or `Temp`.
  - `Eval { value }` for a call statement.
  - `Return { value }`.
  - `If { condition, body, else_body }`.
  - `While { setup, condition, body, label, continues }`: `setup` holds the
    statements that compute the condition on every iteration, and `continues`
    is true when the body contains a `continue`.
  - `Break`, and `Continue { label }`.
- **Temporaries are function-level and recycled.** willow.md §9 allows
  recycling temporaries instead of scoping them in `do ... end` blocks.
  - Temporaries are numbered slots used as a stack: a depth counter starts at 0
    for each source statement, and the function's `temps` is the deepest it
    goes.
  - When a call or helper consumes its operands, the depth drops back to its
    mark, and the result takes the next slot. So `f(f(f(1)))` and long
    left-associative sums use one or two temporaries.
  - Temporaries are declared once at function entry, along with the locals. A
    loop body then declares no locals, so a `goto` to the continue label never
    enters a local's scope, and a function with many statements stays under
    LuaJIT's 200-local limit.
- **Pure operands stay inline.** A subexpression with no call, integer
  arithmetic, or negation (`is_pure`) is used directly. That covers literals,
  names, comparisons, `not`, string `+`, `and`/`or` of pure operands, and unary
  `+`. Such operands cannot fail and cannot be changed by a later call (callers'
  locals are unreachable from callees), so evaluating them where they are used
  is unobservable.
- **Lowering functions.**
  - `lower_value(node)` returns an expression that may be one `Call` or `Helper`
    at the top, with operands that cannot contain calls. Assignments and call
    statements use it directly (`x = f(t1)`).
  - `lower_operand(node)` calls `lower_value`, and if the result is a call or
    helper, moves it into a new temporary with a `Set`.
  - Operands are lowered left before right, and arguments in order, so setup
    statements come out in source order.
  - Unary `+` lowers to its operand.
- **Short circuit.** `and`/`or` with a pure right operand stays a `Binary`.
  Otherwise the left value goes into a result temporary, and the right operand
  is lowered into the body of `If { condition = result }` for `and` or
  `If { condition = Not(result) }` for `or`, which ends with `Set` into the same
  result. A left operand that already sits in the result slot is not copied.
- **Statements.**
  - `Return` lowers its value with `lower_operand`, so `return f()` and
    `return a + b` go through a temporary, and no generated return is a tail
    call.
  - `If` lowers its condition with `lower_operand` and puts the setup before the
    `If`. An `elif`'s condition setup therefore lands inside the outer
    `else_body`.
  - `While` lowers its condition into `setup`. Loop labels count from 1 per
    function, and `continue` records the innermost label.
  - `pass` lowers to nothing.

## Test plan

`tests/unit/lower_test.lua` runs the pipeline through `lower.lower` and prints
lowered functions compactly with a `show` helper:

- statements are joined by `; ` and blocks are braced;
- temporaries print as `t1`;
- helpers print as `add(a, b)#3` with their site;
- `concat` and the comparisons print infix.

`lower_main(statements, helpers)` lowers `main` with the statements indented in
and returns the shown body.

Tests:

- `operands_left_to_right_in_temporaries`: `x = f(1) + g(2)` gives
  `t1 = f(1); t2 = g(2); x = add(t1, t2)#1`.
- `temporaries_are_recycled`:
  - `x = f(f(f(1)))` reuses `t1`, and `temps` is 1;
  - `x = f(1) + f(2) + f(3)` uses two temporaries.
- `pure_operands_stay_inline`: `not (a < b) and c == "s" + "t"` lowers to a
  single `Set` with no temporaries.
- `short_circuit_branches`:
  - `a and f(1)` becomes `t1 = a; if t1 { t1 = f(1) }; x = t1`;
  - `f(1) or g(2)` becomes `t1 = f(1); if (not t1) { t1 = g(2) }; x = t1`.
- `integer_helpers_carry_sites`: `-a * (b - 1)` gives `neg`, `sub`, and `mul`
  in order, with consecutive sites and `sites[id]` equal to each operator's
  span. Unary `+` leaves no node.
- `string_plus_is_concat`: `s + "!"` is `concat`, with no helper or site.
- `returns_never_return_calls`: `return f(1)`, `return a + 1`, `return a`, and
  a bare `return`.
- `print_is_a_helper`: `print(f(1))` gives `t1 = f(1); print(t1)#1`.
- `loops_and_transfers`:
  - a `while` with a call in its condition has that call in `setup`;
  - `continue` and `break` in its body, with `continues` set;
  - a nested loop gets label 2.
- `elif_setup_stays_in_else`: `if f(1): ... elif g(2): ...` puts `t1 = g(2)`
  inside the outer `else_body`.
- `program_shape`: `params`, `locals`, and `temps` of a lowered function, and
  sites numbered across two functions.
