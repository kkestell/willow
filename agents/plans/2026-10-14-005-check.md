# Check

## Goal

Replace the `compiler/check.lua` stub with the type and control-flow checker
for willow.md §4, §5, and §6. `check.check(program)` runs after `bind`. It
assigns a type to every expression, gives every local symbol one stable type,
enforces definite assignment, reachability, loop transfers, and returns, and
reports the first error of each function together. After this change
`willow check` checks programs completely: a valid program exits 0, and an
invalid one prints every collected diagnostic and exits 1. `willow run` reaches
the lower stub for valid files.

## Related code

- `compiler/check.lua` — stub to replace; keeps `M.check(program)`.
- `compiler/bind.lua` — sets `Param.symbol`, `Assign.symbol`, `Name.symbol`
  (symbols are `{ name, span, param }`), `Function.locals`, and `Call.target`
  (a `Function` node or `{ kind = "Builtin", name = "print" }`).
- `compiler/parser.lua` — node shapes; `elif` is a nested `If` in `else_body`.
  Spans are the identifying token: the name for `Assign`, `Name`, `Call`, and
  `Function`; the keyword for statements; the operator for `Unary` and `Binary`.
- `compiler/diag.lua` — gains support for raising several diagnostics at once.
- `compiler/cli.lua:53` — prints one diagnostic today; prints each one after
  this change.
- `tests/unit/{lexer,parser,bind}_test.lua` — their error helpers read the
  raised diagnostic and follow the new shape.

## Decisions

- **Diagnostics are raised as a list.** `diag.error(span, message)` raises a
  one-element list. The new `diag.raise(list)` raises a list of
  `{ span, message }` diagnostics. `diag.is` recognizes the list by its
  metatable. The CLI prints `diag.format(path, d)` for each entry, one per line.
  Every compile failure then has the same shape.
- **Independent errors are per function.** Each function is checked under
  `xpcall`, and the first diagnostic in each function is collected. Signatures
  are fixed before checking, so one function's errors cannot affect another's.
  Within a function the checker stops at the first error, so there are no
  cascades. If any were collected, `check` raises them together in file order.
  The `xpcall` handler returns diagnostics as they are and turns any other error
  into `debug.traceback(err, 2)`, then raises it again unchanged. The CLI
  reports it as an internal compiler error with the original traceback.
- **Types** are the strings `"int"`, `"bool"`, `"str"`, and `"None"`.
  - The checker sets `node.type` on every expression node; lowering reads it, for
    example `Binary` `+` with `type == "str"` is concatenation.
  - It sets `symbol.type` on every symbol. A parameter takes its annotation. A
    local takes its type from its first assignment in source order: the
    annotation if present, otherwise the value's type, including `None`.
- **Expression rules.**
  - Unary `+` and `-` need `int`; `not` needs `bool`.
  - `+` is `int + int` or `str + str`; `-` and `*` are `int` only.
  - `and` and `or` are `bool` only.
  - `==` and `!=` take two operands of the same type, giving `bool`. `<`, `<=`,
    `>`, and `>=` take two `int`s, giving `bool`.
  - An operator error reads `operator '<op>' cannot be applied to <T>` (unary)
    or `... to <T> and <U>` (binary), at the operator.
  - The left operand is checked before the right, so errors come in source
    order.
- **Value contexts** report `expected <T>, received <U>` at the value's span:
  - a reassignment that changes the local's type;
  - an annotated initializer;
  - an argument;
  - a returned value;
  - an `if` or `while` condition, which must be `bool`.
  A bare `return` in a non-`None` function reports `expected <T>, received None`
  at the `return`.
- **Calls.**
  - The argument count must match exactly:
    `'<name>' expects <n> argument(s), received <m>`, at the call. The count is
    checked before the arguments.
  - Each argument must match its parameter's type, and the call's type is the
    return type.
  - `print` takes exactly one argument, which can be any of the four types, and
    has type `None`.
- **Annotations.** An annotated `Assign` on a parameter raises
  `cannot annotate parameter '<name>'`. An annotated `Assign` on a symbol whose
  type is already set raises
  `only the first assignment to '<name>' can have an annotation`. The checker
  walks statements in source order, with an `if` body before its `else` body,
  so "type already set" means "an earlier assignment exists".
- **Definite assignment.**
  - `assigned` is a set of symbols. Parameters are in it at entry, and an
    `Assign` adds its symbol after checking the value.
  - Reading a `Name` whose symbol is not in the set raises
    `variable '<name>' may be used before assignment`.
  - `check_block(body, assigned, in_loop)` copies the set and returns
    `(assigned_after, transfers)`.
  - An `If` checks each branch from a copy, and a missing `else` counts as an
    empty branch that falls through. Each branch's result contains the entry
    set, so joining only adds to the current set:
    - if both branches transfer, the `if` transfers;
    - if one transfers, add the other's set;
    - otherwise add the symbols present in both.
  - A `While` checks its body from a copy with `in_loop = true` and discards the
    result. The loop never counts as a transfer.
- **Control transfer.**
  - `return`, `break`, `continue`, and an `if` whose branches both transfer are
    transfers. A statement after a transfer in the same block raises
    `unreachable statement`.
  - `break` and `continue` with `in_loop` false raise
    `'break' outside of a loop` or `'continue' outside of a loop`.
  - A non-`None` function whose body does not transfer raises
    `function '<name>' must return a value on every path` at its name. At
    function level only `return` can transfer, because loop transfers outside
    a loop are already errors.

## Test plan

`tests/unit/check_test.lua` runs `lexer.lex`, `parser.parse`, `bind.bind`, and
`check.check`. Helpers:

- `eq`.
- `check_source(source)` returns the program.
- `check_errors(source)` returns the collected diagnostics as
  `"line:col: message"` lines joined by `"\n"`, and fails on success or a
  non-diagnostic error.
- `in_main(statements, helpers)` indents statements into `main` and appends
  any helper functions a test needs.

Tests:

- `expression_and_local_types`: `node.type` and `symbol.type` for literals,
  int and str `+`, comparisons, `not`, a call's return type, and a local
  inferred as `None` from `print`.
- `operator_type_errors`: `1 + "a"`, `"a" * 2`, `-"a"`, `not 1`,
  `1 and True`, `"a" < "b"`, and `1 == "a"`.
- `equality_on_all_types`: `==` and `!=` on `int`, `bool`, `str`, and `None`.
- `conditions_must_be_bool`: `if 1:` and `while "s":`.
- `calls_check_arity_and_arguments`: too few and too many arguments, a wrong
  argument type, a call's return type checked at its use, `print` with zero or
  two arguments, and `print` with each type.
- `locals_keep_one_type`: reassignment to another type, and incompatible
  assignments across `if`/`else`.
- `annotations`: a mismatched initializer, an annotation on a later assignment,
  an annotation in an `else` after the `if` branch assigned, an annotated
  parameter, and an accepted `x: None = print(1)`.
- `definite_assignment`:
  - rejected: a read before assignment, assignment only in an `if` without
    `else`, and assignment only in a loop body read after the loop;
  - accepted: `if`/`elif`/`else` all assigning, and one branch returning while
    the other assigns.
- `unreachable_code`:
  - rejected: after `return`, after `break` in a loop, and after an
    `if`/`else` that both return;
  - accepted: after an `if` without `else` that returns.
- `missing_return`:
  - rejected: no return, `while True:` containing the only return, and a bare
    `return` in an `int` function;
  - accepted: `if`/`else` both returning, and a `None` function falling off its
    end.
- `loop_transfers_outside_loop`: `break` and `continue` outside a loop, and
  accepted inside an `if` inside a `while`.
- `independent_errors_collected`: two functions with errors report both in file
  order, and a function with two errors reports only its first.

`tests/programs/type_errors.wlo` with `type_errors.err`: two functions with one
type error each, printed as two diagnostics through the CLI with exit status 1.
