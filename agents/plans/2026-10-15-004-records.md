# Records

## Goal

Add `class` record declarations, constructors, field reads, and field
assignment (willow.md §16). When done, the §16 example checks, builds, and runs
with the output in its comment; records are nominal, mutable, shared by
reference, and rejected by `==` and `print`; and constructor arguments and field
assignments evaluate in Python's order.

## Related code

- `compiler/parser.lua` — `parse_type`, `parse_postfix` (`. NAME` without `(` is
  an error today), `parse_assignment_or_call`, the file-scope loop, and the
  `unsupported` reserved words (`class`).
- `compiler/bind.lua` — `builtins`, the file-level `functions` table, duplicate
  and redefinition checks, `resolve_expression`, and `resolve_block`.
- `compiler/check.lua` — the `Call` branch, `scalar`, `M.check`.
- `compiler/lower.lua` — `is_pure`, `lower_operand`, the `Call` branch, and
  `IndexAssign` lowering.
- `compiler/emit.lua` — `expr` and `M.mangle`.

## Decisions

- **Types.** A record type is its name, so `Node`, `Node | None`, and
  `list[Node]` are type strings like the others and nominal typing is string
  equality. `parse_type` accepts a `NAME` as a type and gives every `Type` node a
  `records` list of `{ name, span }` for the record names it mentions, including
  nested ones, so bind can validate them without parsing type strings.
- **Syntax.** `class NAME:` followed by an indented block of `NAME : Type` lines
  parses to `Record { name, fields }` with `FieldDecl { name, type }` entries;
  any other line in the body is `record bodies hold only field declarations`.
  The program node holds `functions` and `records`; any other file-scope token is
  `only function and class definitions are allowed at file scope`. `class` leaves
  the unsupported reserved words.
- **Fields in expressions.** `. NAME` without `(` builds `Field { object, name }`
  with the name token's span, replacing `methods must be called`; an uncalled
  method such as `items.append` becomes a check error instead.
  `Field = value` builds `FieldAssign { object, name, value }`, and `:` after a
  `Field` is `only a name can have an annotation`.
- **Binding.** One `declarations` table holds functions and records. A name taken
  by a built-in is `cannot redefine built-in function '<name>'`; a name already
  declared is `duplicate function '<name>'` or `duplicate record '<name>'`
  after the new declaration's kind; a repeated field is
  `duplicate field '<name>'`. Every record name in a `Type` node (parameters,
  returns, local annotations, fields) must be a record: `unknown type '<name>'`.
  A call to a record name targets the `Record` node. A record name used as a
  value is `record '<name>' cannot be used as a value`. Locals already shadow
  call targets, and annotations are resolved against `declarations` only, so a
  local never shadows a type. Resolution walks `Field` objects and `FieldAssign`
  values and objects.
- **Checking.** `M.check` builds a `records` map from name to `Record` node and
  passes it to `check_function`. A constructor call checks exact arity and each
  argument against its field type (with the field type as the expected type, so
  displays work), and has the record's type. `Field` on a record type has the
  field's type; a missing field is `record <name> has no field '<field>'`; any
  other object type is `type <type> has no field '<field>'`. `FieldAssign` checks
  the value against the field type the same way. `scalar` already excludes
  record names, so `==`, `print`, and `in` reject records, and a `Field` operand
  of `is` yields no facts.
- **Representation.** A record is a Lua table keyed by field names passed
  through `M.mangle`, so a field named like a Lua keyword still works. Field
  reads and writes are plain table access; no runtime helper is needed.
- **Lowering.**
  - A constructor lowers its arguments with `lower_operand` in order to
    `Construct { names, values }`, which emits `{ value = a, next = b }`.
    `is_pure` treats a constructor call as pure when its arguments are.
  - A field read lowers to `Field { object, name }`. A later call can change a
    field, so `is_pure` treats `Field` as impure and `lower_operand` spills a
    `Field` into a temporary as it does calls; a field read assigned directly is
    not spilled.
  - `FieldAssign` lowers the value, then the object, and emits
    `Set { target = Field { object, name }, value }`.
  - A constructor call statement leaves nothing to evaluate after its
    arguments, as `float(x)` does.
- **Emission.** `Field` emits `object.name`, parenthesizing an object that is not
  a local or temporary (`({ x = 1 }).x`). `Construct` emits a table constructor
  with every field, including `nil` ones.

## Test plan

- `tests/unit/parser_test.lua`: a record with several fields, including a self
  and optional field type; an empty body, a method, `pass`, and an assignment in
  a body rejected; record types in annotations (`Node`, `list[Node] | None`);
  field access chains (`a.b.c`, `rows[0].name`), field assignment, and an
  annotation on a field rejected.
- `tests/unit/bind_test.lua`: duplicate record, record and function with the
  same name, record named `len`, duplicate field; unknown type in a parameter,
  a field, and a local annotation; forward and self references; a constructor
  call target; a local shadowing a constructor (`cannot call local variable`)
  while annotations still name the record; a record used as a value.
- `tests/unit/check_test.lua`: constructor arity and argument types, including
  `None` for an optional field and a display for a list field; field read and
  write types; unknown field; field on a non-record and on an unnarrowed
  optional record; two records with the same fields not assignable to each
  other; `==` and `print` on records; a field operand of `is` not narrowing.
- `tests/unit/lower_test.lua`: field reads spilled before a later call;
  `FieldAssign` order (value, object); constructor arguments in order.
- `tests/programs/records.wlo` with `.out`: the §16 example; mutation through an
  alias and through a function argument; a linked list built and walked with
  narrowing; a field named like a Lua keyword; constructor argument and field
  assignment evaluation order shown with printing functions. Expected output
  comes from running the program in Python with `@dataclass` added to each
  class.

1. `compiler/parser.lua`: record types and `records` lists in `parse_type`;
   `parse_record`; file scope; `Field` and `FieldAssign`.
2. `compiler/bind.lua`: `declarations`, record and field checks, type
   validation, constructor targets, and resolution of the new nodes.
3. `compiler/check.lua`: `records`, constructor calls, `Field`, `FieldAssign`.
4. `compiler/lower.lua`: `Construct`, `Field`, `FieldAssign`, `is_pure`, and
   spilling field reads.
5. `compiler/emit.lua`: `Field` and `Construct`.
6. Tests as listed above.
7. `agents/todo.md`: tick the milestone.
