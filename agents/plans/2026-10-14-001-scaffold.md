# Scaffold

## Goal

Lay out the repository from willow.md §9 so later milestones each have a home:
a `willow` launcher, one module per compiler pass, shared span, diagnostic, and
AST modules, the runtime file, the examples, and a test runner that runs unit
tests from `tests/unit/` and program tests from `tests/programs/`. After this
change `willow check` and `willow run` reach the pass pipeline, which stops at
the lexer stub with an internal compiler error until the Lexer milestone lands.

## Related code

- `Makefile` — `test` runs `tests/run.lua` over `tests/*_test.lua`; becomes
  `tests/unit/*_test.lua` plus `tests/programs/*.wlo`.
- `tests/run.lua` — runs unit test files given on the command line (each returns
  a table of functions); gains program tests.
- `agents/todo.md` — the Scaffold milestone and its items get checked off.

## Decisions

- **Pass interfaces.** Each pass module returns a table with one entry function:
  `lexer.lex(source)` returns tokens; `parser.parse(tokens)` returns the program
  node; `bind.bind(program)` and `check.check(program)` annotate the tree in
  place; `lower.lower(program)` returns the lowered program;
  `emit.emit(lowered, path)` returns Lua text. Until its milestone, each entry
  function raises `"<pass> not implemented"`.
- **Module paths.** Modules are required as `compiler.<name>`. `cli.lua` sets
  `package.path` to `<root>/?.lua`, where `<root>` comes from its own `arg[0]`,
  the same way `tests/run.lua` does.
- **Spans.** `span.new(line, col, first, last)` returns
  `{ line, col, first, last }`: one-based line, code-point column, and inclusive
  byte offsets, so `source:sub(span.first, span.last)` is the spanned text.
- **AST nodes.** `ast.node(kind, span, fields)` sets `kind` and `span` on the
  plain `fields` table and returns it.
- **Diagnostics.** `diag.error(span, message)` raises a diagnostic table marked
  with a private metatable; `diag.is(value)` tests for that mark;
  `diag.format(path, d)` returns `path:line:col: error: message`. The CLI treats
  any other raised value as an internal compiler error and prints
  `internal compiler error: <message>` with a traceback.
- **Scaffold CLI.** `cli.lua` accepts `check <file>` and `run <file>`; anything
  else prints usage and exits 1. Both read the file, then lex, parse, bind, and
  check; `run` also lowers, emits, loads the Lua with chunk name `=<path>`, and
  calls it after compilation succeeds. A diagnostic or internal error goes to
  stderr with exit 1; an unreadable file prints `error: <io message>` and
  exits 1. `build` and option handling come with the CLI milestone.
- **Launcher.** `willow` is a POSIX `sh` script. It follows symlinks on `$0` so a
  link installed elsewhere still finds the checkout, then
  `exec "$root/vendor/luajit/src/luajit" "$root/compiler/cli.lua" "$@"`.
- **Runtime file.** `runtime/core.lua` holds the runtime helpers as Lua source
  text that the emitter inlines into generated programs. It starts with only its
  header comment.
- **Program test format.** A program test is `tests/programs/NAME.wlo` with
  optional `NAME.out` (expected stdout) and `NAME.err` (expected stderr); a
  missing file means empty output. The expected exit status is 1 when `NAME.err`
  exists and 0 otherwise. The runner executes `willow run NAME.wlo` from the
  test's own directory, so expected diagnostics read `NAME.wlo:line:col: ...`.
- **Runner dispatch.** `tests/run.lua` treats each `.wlo` argument as one program
  test and every other argument as a unit test file. Program tests run through
  `io.popen` with `cd <dir> && <abs willow> run <name> >tmp_out 2>tmp_err; echo $?`
  and compare stdout, stderr, and exit status exactly. The launcher path is made
  absolute once at startup with `cd <root> && pwd`. Arguments are single-quoted
  for the shell.

## Test plan

- `make test` reports `0 passed, 0 failed`; no tests exist yet in either
  directory.
- `./willow` with no arguments, an unknown command, or an extra argument prints
  usage and exits 1.
- `./willow check examples/hello.wlo` and `./willow run examples/sums.wlo` exit 1
  with `internal compiler error: ... lexer not implemented` and a traceback.
- `./willow check missing.wlo` prints `error: missing.wlo: No such file or
  directory` and exits 1.
- The launcher works through a symlink placed in another directory.
- Exercise the program-test path by hand with temporary files in
  `tests/programs/`: one whose `.err` matches the stub's output passes, and one
  with a wrong `.out` fails with a readable report. Remove them afterward.

## Implementation plan

1. `compiler/span.lua`, `compiler/ast.lua`, `compiler/diag.lua` as described in
   Decisions.
2. `compiler/lexer.lua`, `parser.lua`, `bind.lua`, `check.lua`, `lower.lua`,
   `emit.lua`: one entry function each, with a one-line header naming what the
   pass consumes and produces.
3. `compiler/cli.lua` with the scaffold CLI.
4. `willow` launcher, executable.
5. `runtime/core.lua` with its header comment.
6. Examples:
   - `examples/hello.wlo`: `main` prints `"Hello, Willow"`;
   - `examples/sums.wlo`: the §2 program, verbatim;
   - `examples/fibonacci.wlo`: recursive and looping Fibonacci;
   - `examples/grades.wlo`: letter grades with `if`/`elif`/`else`;
   - `examples/primes.wlo`: the primes below 50.
7. `tests/run.lua`: add program tests and dispatch on extension; update the
   header comment to describe both test kinds and the program test format.
8. `Makefile`: `test` passes `$(wildcard tests/unit/*_test.lua)` and
   `$(wildcard tests/programs/*.wlo)`.
9. `agents/todo.md`: check the Scaffold milestone and its items.
