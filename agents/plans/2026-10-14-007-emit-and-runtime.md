# Emit and runtime

## Goal

Replace the `compiler/emit.lua` stub and fill in `runtime/core.lua` so that
`emit.emit(lowered, path)` returns one standalone, readable, deterministic Lua
program (willow.md §7–§10). After this change `willow run` executes Willow
programs end to end:

- integer arithmetic is checked, and `-0.0` is normalized;
- `print` output matches §7;
- a runtime failure prints `file:line:col: error: message` followed by the
  Willow caller frames, then exits with status 1.

## Related code

- `compiler/emit.lua` — stub to replace; keeps `M.emit(lowered, path)`.
- `runtime/core.lua` — today only a header comment; becomes the runtime source
  text that `emit` inlines.
- `compiler/lower.lua` — the input. `{ functions, sites }`:
  - each function is `{ name, span, params, locals, temps, body }`;
  - statements are `Set`, `Eval`, `Return`, `If`, `While` (`setup`,
    `condition`, `body`, `label`, `continues`), `Break`, and `Continue`, each
    with a `span`;
  - expressions are `Literal`, `Local`, `Temp`, `Not`, `Binary` (`== != < <= > >=
    and or concat`), `Call`, and `Helper` (`add sub mul neg print`, with `site`).
  - Temporaries are function-level slots, so no local is declared below a
    function's first line.
- `compiler/cli.lua:25` — `run` loads the emitted text with chunk name
  `"=" .. path` and calls it.
- `tests/run.lua` — program tests compare stdout, stderr, and exit status.

## Decisions

- **File layout,** top to bottom, one statement per line:
  1. `-- Generated by willow; requires LuaJIT 2.1.`
  2. `local __wlo_path = <quoted path>` and `local __wlo_sites, __wlo_lines`.
  3. The lines of `runtime/core.lua`. `emit` finds the file with
     `package.searchpath("runtime.core", package.path)` and reads it once when
     the module loads.
  4. `local <mangled function names>`, forward-declaring every function in
     source order.
  5. Each function as `function name(params)`. Its first body line is
     `local <locals>, __wlo_t1, ...` when it has locals or temporaries. Then
     come the statements, indented two spaces per level, and `end`.
  6. `__wlo_sites = { {line, col}, ... }`, one entry per line in site order.
  7. `__wlo_lines = { [lua_line] = {line, col, "function"}, ... }` in increasing
     line order.
  8. `__wlo_run(main)`.

  The tables come after the functions because their line numbers are only known
  once the functions are emitted. The runtime reads them as upvalues assigned
  before `__wlo_run`.
- **Source map.** `emit` collects output lines in an array, so a line's index is
  its Lua line number. It records `__wlo_lines[n]` for:
  - every statement line, using the statement's span: `Set`, `Eval`, `Return`,
    `Break`, `goto`, and the `if`/`elseif`/`while` header lines;
  - a loop's `if not (...) then break end` line, using the `While` span;
  - the function header and its `local` line, using the function's span.
  Lines holding only `else`, `end`, or a label are not mapped.
- **Statements.**
  - `Set` → `target = value`; `Eval` → `value`; `Return` → `return value` or
    `return`.
  - `If` → `if c then ... else ... end`. An `else_body` that is exactly one
    `If` is emitted as `elseif`.
  - `While` with empty `setup` → `while c do ... end`. Otherwise:

    ```lua
    while true do
      <setup>
      if not (<c>) then break end
      <body>
    end
    ```
  - When `continues` is set, `::__wlo_continue_N::` is the loop body's last
    line, and `Continue` is `goto __wlo_continue_N`.
  - `Break` → `break`.
- **Expressions.**
  - Literals: numbers use `string.format("%d", v)`; strings use `M.quote`;
    booleans print as `true`/`false`; `None` is `nil`.
  - `Local` → `M.mangle(symbol.name)`; `Temp` → `__wlo_tN`.
  - `Not` → `not <operand>`.
  - `Binary` uses the Lua operators (`!=` is `~=`, `concat` is `..`). A nested
    `Binary` is parenthesized, so Lua precedence never matters.
  - `Call` → `mangled(args)`.
  - `Helper` → `__wlo_<name>(args, site)`.
- **`M.quote(s)`** returns a double-quoted Lua literal. It escapes `\\`, `"`,
  `\n`, `\r`, and `\t`, and writes every other byte below 32, and 127, as a
  three-digit `\ddd` so a following digit cannot join the escape. Bytes of 128
  and above pass through unchanged.
- **`M.mangle(name)`** appends `_` to a name that:
  - is a Lua keyword (`and break do else elseif end false for function goto if
    in local nil not or repeat return then true until while`),
  - ends in `_`, or
  - starts with `__wlo_`.

  Every changed name ends in `_` and no unchanged name does, so mangling is
  one-to-one. No internal name ends in `_`, so user names never collide with
  `__wlo_` names. User functions are declared after the runtime, so a function
  named `io` or `error` cannot shadow the globals the runtime uses.
- **Runtime (`runtime/core.lua`).** Every name in it starts with `__wlo_`.
  - `__wlo_source = debug.getinfo(1, "S").source` identifies this chunk's
    frames.
  - `__wlo_fail(category, message, site)` raises
    `{ category, message, location = __wlo_sites[site] }`.
  - `__wlo_check(value, site)` raises `overflow` / `integer overflow` for NaN
    or a value outside ±9007199254740991, and returns `0` for any zero, which
    normalizes `-0.0`. `__wlo_add`, `__wlo_sub`, `__wlo_mul`, and `__wlo_neg`
    pass their result through it.
  - `__wlo_print(value, site)` formats `nil` as `None`, booleans as
    `True`/`False`, numbers with `%d`, and strings unchanged. It writes the text
    and `"\n"` to `io.stdout` and flushes. A failed write or flush raises
    `io` / `cannot write output: <reason>`. Flushing on every print attributes
    the failure to the `print` that hit it.
  - `__wlo_report(err)` is the `xpcall` handler:
    - It walks `debug.getinfo(level, "Sl")` from level 1, keeping frames whose
      `source` is `__wlo_source` and whose `currentline` is in `__wlo_lines`.
      Runtime and wrapper lines are never mapped, so they drop out.
    - A non-table error is a raw VM error. It becomes
      `{ category = "vm", message = <text without its "chunk:line: " prefix>,
      location = innermost frame }`.
    - It returns `path:line:col: error: message`, then one line per frame:
      `  in <fn> at path:line:col` for the innermost frame and
      `  called from <fn> at path:line:col` for the rest.
    - Past 20 frames it ends with `  ... N more frames`, so a stack overflow
      stays readable.
  - `__wlo_run(main)` calls `xpcall(main, __wlo_report)`. On failure it writes
    the report and a newline to stderr and calls `os.exit(1)`.
- **Temporaries checklist item.** The Lower milestone recycles temporaries as
  function-level locals (willow.md §9's alternative to `do ... end`), so no
  loop body declares a local. The todo item is reworded to that approach when
  it is checked.

## Test plan

`tests/unit/emit_test.lua`:

- `quote_round_trips`: for `\\ \' \" \n \r \t`, a NUL followed by `1`, other
  control bytes, DEL, and non-ASCII text, `load("return " .. emit.quote(s))()`
  equals `s`.
- `mangle_is_one_to_one`:
  - `end`, `nil`, `x_`, and `__wlo_t1` change;
  - `total` and `x` stay the same;
  - `end` and `end_` mangle to different names.
- `output_is_deterministic`: emitting the same source twice gives identical text
  containing no `0x` addresses.
- `one_call_per_line`: in the function section of the output for a program with
  nested calls and arithmetic, no line has more than one `name(`. Function
  header lines are exempt.
- `write_failures_are_runtime_errors`: run a program through the launcher with
  stdout closed (`>&-`). It exits 1 with
  `NAME.wlo:2:5: error: cannot write output: ...` and an `in main at` frame.
- `stack_overflow_reports_innermost_frame`: unbounded recursion through the
  launcher exits 1. The first stderr line is
  `NAME.wlo:L:C: error: stack overflow` at the recursive call, followed by 20
  frame lines and `... more frames`.

The two launcher tests write the source to a temporary file named `NAME.wlo`
in a fresh directory and run `willow run` from there.

Program tests in `tests/programs/`, each a `.wlo` with `.out` or `.err`:

- `print_values`: integers including both bounds, a negative number, `True`,
  `False`, `None`, a string with escapes and non-ASCII text, concatenation,
  and `0 * -1`, `-(0)`, and `0 - 0` all printing `0`.
- `evaluation_order`:
  - arguments run left to right (logging helpers print as they run);
  - `and`/`or` skip their right operand;
  - `log("a") == log("b")` prints `a`, then `b`, then `True`.
- `control_flow`:
  - `while` with `continue` and `break`, and nested loops;
  - a loop condition containing a call;
  - `if`/`elif`/`else`;
  - recursion and mutual recursion (`is_even`/`is_odd`).
- `lua_keyword_names`: functions and locals named `end`, `local`, `nil`, and
  `then` work and print correctly.
- `overflow_frames`: `print(safe(1) + wrap(2))` in `main`, where `wrap` does
  `return boom(n)` and `boom` overflows a multiplication. The expected stderr
  is:
  - the error at the `*` column;
  - `in boom` at that column;
  - `called from wrap` at the `boom` call column in the `return`;
  - `called from main` at the `wrap` call column, not the `safe` one.

  Stdout has what was printed before the failure.
- Existing `tests/programs/sums`-style coverage comes from `examples/sums.wlo`:
  a `sums` program test with the §2 output.
