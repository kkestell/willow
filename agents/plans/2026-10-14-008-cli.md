# CLI

## Goal

Finish the command-line interface from willow.md §8:

- `willow check <file>`, `willow run <file>`, and
  `willow build <file> -o <output>`, rejecting unknown commands, unknown
  options, and extra arguments;
- `build` writes the generated Lua through a temporary sibling file and renames
  it into place, so a failed build never touches an existing output;
- `build` refuses an output path that is the input file under another name (the
  same path, a relative alias, a symlink, or a hardlink), comparing device and
  inode through LuaJIT `ffi` `stat`.

## Related code

- `compiler/cli.lua` — parses `check`/`run` today, compiles, and for `run` loads
  and calls the emitted chunk. It gains `build`, argument parsing, the alias
  check, and the atomic write.
- `compiler/emit.lua` — `emit.emit(lowered, path)` returns the standalone Lua
  text, and `path` is recorded in it for diagnostics.
- `tests/unit/emit_test.lua:23` — the `run` helper that drives the launcher
  through `io.popen`; the CLI tests follow its pattern.

## Decisions

- **Arguments.** `args[1]` must be `check`, `run`, or `build`. The remaining
  arguments are read left to right:
  - for `build`, `-o` takes the next argument as the output path;
  - any other argument starting with `-` is an unknown option;
  - the first plain argument is the input, and any later one is unexpected.

  A usage error prints `error: <reason>` and then the usage text below, and exits 1:

  ```text
  usage: willow check <file>
         willow run <file>
         willow build <file> -o <output>
  ```

  The reasons are:
  - `missing command`;
  - `unknown command '<x>'`;
  - `unknown option '<x>'`;
  - `unexpected argument '<x>'`;
  - `missing input file`;
  - `-o needs a path`;
  - `-o given more than once`;
  - `build needs -o <output>`.
- **Order of work.** Parse arguments, read the input, check aliasing (for
  `build`), then compile. A failed compile exits before anything is written or
  run.
  - `compile` emits and `load`s the Lua for `run` and `build` inside the
    existing `xpcall`, so invalid generated Lua is reported as an internal
    compiler error before anything is written.
  - `run` calls the chunk; `build` writes the text.
- **Atomic write.** `build` opens `<output>.tmp` with mode `"wbx"` (exclusive
  create). That keeps umask permissions and never clobbers an existing file,
  including the input. It then writes, flushes, closes, and calls
  `os.rename(tmp, output)`. On any failure it removes the temporary file and
  prints `error: cannot write <output>: <reason>`, exiting 1. A leftover
  `<output>.tmp` from an interrupted build makes the next build fail with that
  message instead of overwriting it.
- **Alias check.** `same_file(input, output)` compares the `dev` and `ino`
  fields of `ffi.C.stat` for both paths. An output that cannot be `stat`ed (for
  example, one that does not exist yet) is never an alias. A match prints
  `error: output <output> is the input file` and exits 1.

  `stat` follows symlinks, so a symlink to the input matches, and a hardlink
  shares the inode. Only `dev` and `ino` are declared, and the struct is padded
  past any platform's `struct stat`:
  - macOS: `int32_t dev; uint16_t mode; uint16_t nlink; uint64_t ino`, with the
    symbol `stat$INODE64` on x86-64;
  - Linux (glibc 2.33+ and musl export `stat`): `uint64_t dev; uint64_t ino`.

## Test plan

`tests/unit/cli_test.lua` drives the launcher through `io.popen` in a fresh
temporary directory whose name contains a space. A helper `willow(dir, args)`
returns the exit status, stdout, and stderr. Tests:

- `usage_errors`: no arguments, an unknown command, an unknown option, an extra
  argument, `-o` with `run`, `build` without `-o`, and `-o` without a path. Each
  exits 1 with the expected `error:` first line and the usage text.
- `check_does_not_execute`: a program that prints exits 0 with empty stdout.
  Invalid source exits 1 with its diagnostic.
- `build_matches_run`: `build` exits 0 with no output of its own and leaves no
  `.tmp` file. The built file, copied to another directory and run there with
  the bundled `luajit`, prints the same stdout as `willow run`.
- `failed_build_preserves_output`: an existing output survives an invalid
  source unchanged, and no `.tmp` file is left.
- `output_alias_rejected`: the input path itself, `./name.wlo`, a symlink to the
  input, and a hardlink to the input are all rejected. The input is unchanged
  afterward.
- `unwritable_output`: an output in a missing directory exits 1 with
  `error: cannot write`.
