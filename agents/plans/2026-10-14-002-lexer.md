# Lexer

## Goal

Replace the `compiler/lexer.lua` stub with a lexer for willow.md §3 and §4.
`lexer.lex(source)` returns the token list for valid source and raises one
diagnostic, through `diag.error`, at the first invalid source it finds. With the
lexer in place, `willow check` and `willow run` report lexical errors as
`file:line:col: error: message` and reach the parser stub for valid files.

## Related code

- `compiler/lexer.lua` — stub to replace; keeps `M.lex(source)`.
- `compiler/span.lua` — `span.new(line, col, first, last)`; every token gets one.
- `compiler/diag.lua` — `diag.error(span, message)` raises the diagnostic the CLI
  formats.
- `compiler/cli.lua` — already calls `lexer.lex(source)` and formats diagnostics;
  no change.
- `tests/run.lua` — runs `tests/unit/*_test.lua` and `tests/programs/*.wlo`.

## Decisions

- **Tokens.** A token is `{ kind = ..., value = ..., span = ... }`. Kinds:
  - `NAME` (value: the identifier), `INT` (value: the number), `STRING` (value:
    the decoded text).
  - Each reserved word, including `int`, `bool`, and `str`, is its own kind,
    spelled as the word (`def`, `True`, `None`, `lambda`, ...). Reserved words
    with no supported construct are still tokens; the parser rejects them.
  - Each supported operator or punctuation mark is its own kind, spelled as the
    text: `->` `==` `!=` `<=` `>=` `<` `>` `=` `+` `-` `*` `(` `)` `,` `:`.
  - `NEWLINE`, `INDENT`, `DEDENT`, `EOF`.
- **Spans.** `line` is one-based; `col` counts code points from the start of the
  line, computed as the byte distance minus the UTF-8 continuation bytes
  (`[\128-\191]`) between the line start and the position; `first` and `last`
  are inclusive byte offsets into the original source. CRLF is not normalized,
  so offsets always index the original source. `NEWLINE` spans its `\n` or
  `\r\n`. `INDENT` and `DEDENT` are empty spans (`last = first - 1`) at the
  first token of their line. A `NEWLINE` added for a missing final newline, the
  closing `DEDENT`s, and `EOF` are empty spans at `#source + 1`.
- **Validation pass.** Before tokenizing, `validate(source)` walks the whole file
  once and raises `invalid UTF-8` at the first malformed sequence (overlong
  forms, surrogates, and code points above U+10FFFF included) and
  `bare carriage return; line endings must be LF or CRLF` at a `\r` not followed
  by `\n`. Because this runs first, comments and strings are covered, and the
  tokenizer can treat `\r` as the start of a CRLF newline.
- **Indentation.** Levels are fixed at four spaces, so the lexer tracks one
  integer `level` instead of a stack. At the start of a logical line outside
  parentheses:
  - Leading spaces followed by `#`, a newline, or the end of the file make a
    blank or comment-only line; it produces no tokens and any width is allowed.
  - Otherwise the width must be a multiple of four
    (`indentation must be a multiple of four spaces`) and may rise by at most
    one level (`unexpected indent`). One level up adds `INDENT`; each level down
    adds a `DEDENT`.
  - Errors point at the first non-space character.
- **Newlines.** Outside parentheses, a newline ends a logical line with
  `NEWLINE` only if the line produced a token. A paren depth counter suppresses
  `NEWLINE`, `INDENT`, and `DEDENT` while it is above zero; leading spaces on a
  continuation line are ordinary whitespace. At the end of the file the lexer
  adds `NEWLINE` if the last line has tokens without one, then a `DEDENT` per
  open level, then `EOF`.
- **Tabs.** A tab in leading whitespace, between tokens, or on a blank line
  raises `tabs are not allowed outside strings and comments` at the tab. Comment
  text is skipped unexamined to the end of the line.
- **Identifiers.** `[%a_][%w_]*`; LuaJIT's pattern classes are ASCII-only.
- **Integers.** At a digit, take the run `[%w_.]+`. Any non-digit in it raises
  `invalid integer literal '<text>'`, which covers floats, hex, underscores, and
  suffixes. Then `integer literal has leading zeros` for a multi-digit literal
  starting with `0`, then `integer literal out of range` when the digit string
  is longer than `"9007199254740991"`, or the same length and greater by string
  comparison. Only then does `tonumber` run.
- **Strings.** Read byte by byte from the opening quote to the matching quote,
  decoding `\\ \' \" \n \r \t`. A newline or end of file before the closing
  quote, including right after a backslash, raises
  `unterminated string literal` at the opening quote. Any other escaped
  character raises `unknown escape sequence '\<char>'` at the backslash. Other
  bytes, including tabs and non-ASCII text, are copied unchanged.
- **Operators.** Longest match over lengths 3, 2, and 1 against two sets: the
  supported operators above, and the unsupported
  `**= //= <<= >>= ** // << >> += -= *= /= %= &= |= ^= := / % & | ^ ~`. An
  unsupported match raises `unsupported operator '<text>'`.
- **Other characters.** Anything else outside strings and comments raises
  `unexpected character '<char>'`, where `<char>` is the full UTF-8 character.

## Test plan

`tests/unit/lexer_test.lua`, with small helpers `kinds(source)` (kinds joined by
spaces), `lex_error(source)` (`"line:col: message"` from the raised diagnostic;
fails the test if lexing succeeds or raises anything else), and `eq`:

- `tokens_for_a_function`: kinds and the `NAME`/`INT` values for a two-line
  function.
- `crlf_matches_lf`: same kinds for CRLF and LF versions; `NEWLINE` spans the
  CRLF pair.
- `bare_cr_rejected`: in code, in a comment, and in a string, each at the CR.
- `invalid_utf8_rejected`: a stray byte, an overlong form, and a surrogate, at
  the right line and column.
- `columns_count_code_points`: after `'héllo'`, the next token's `col` counts
  code points while `first` counts bytes; the `STRING` value keeps `é`.
- `tabs_rejected_outside_strings_and_comments`: tab in indentation, between
  tokens, and on a blank line; a tab inside a string and a comment lexes.
- `blank_and_comment_lines_ignored`: blank and comment-only lines at odd widths
  inside and after a block.
- `missing_final_newline`: a file ending in a nested block without a newline
  gives `NEWLINE DEDENT DEDENT EOF`.
- `newlines_inside_parentheses`: a multiline call with odd continuation
  indentation gives no `NEWLINE`, `INDENT`, or `DEDENT` inside the parentheses.
- `indentation_errors`: two-space indentation and a two-level jump.
- `keywords_and_names`: reserved words, including `int`, `bool`, `str`, `None`,
  and an unsupported one such as `lambda`, are their own kinds; `print` and
  `x_1` are `NAME`.
- `integer_literals`: `0` and `9007199254740991` values; `007`,
  `9007199254740992`, a 20-digit literal, `1.5`, `0x1F`, and `1_000` rejected.
- `string_literals`: both quote styles, every escape, non-ASCII text; an unknown
  escape, a physical newline, and end of file rejected.
- `operators`: every supported operator lexes as its own kind.
- `unsupported_operators`: `/ // % ** += := & | ^ ~ << >>` each raise
  `unsupported operator`.
- `unexpected_characters`: `[` and a non-ASCII character outside a string.

`tests/programs/unknown_escape.wlo` with `unknown_escape.err`: an unknown escape
on line 2 reported as `unknown_escape.wlo:2:<col>: error: unknown escape
sequence '\q'` with exit status 1, through the real CLI.
