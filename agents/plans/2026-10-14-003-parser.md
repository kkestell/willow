# Parser

## Goal

Replace the `compiler/parser.lua` stub with a recursive-descent parser for
willow.md §3 and §5. `parser.parse(tokens)` turns the lexer's token list into a
`Program` tree, or raises one diagnostic through `diag.error` at the first
syntax error. After this change `willow check` and `willow run` report syntax
errors and reach the bind stub for valid files.

## Related code

- `compiler/parser.lua` — stub to replace; keeps `M.parse(tokens)`.
- `compiler/lexer.lua` — tokens are `{ kind, value, span }`. Reserved words and
  operators use their own text as `kind`; `NAME`, `INT`, `STRING`, `NEWLINE`,
  `INDENT`, `DEDENT`, and `EOF` are the others. `+=`, `:=`, and the other
  unsupported operators never reach the parser.
- `compiler/ast.lua` — `ast.node(kind, span, fields)`; every node is built with
  it.
- `compiler/diag.lua`, `compiler/span.lua` — error raising and spans.
- `tests/unit/lexer_test.lua` — style for helpers (`eq`, error capture) to follow.

## Decisions

- **Nodes.** Plain tables from `ast.node`:
  - `Program { functions }`
  - `Function { name, params, return_type, body }`; `Param { name, type }`;
    `Type { name }` where `name` is `int`, `bool`, `str`, or `None`
  - Statements: `Assign { name, annotation, value }` (`annotation` is a `Type`
    or nil), `CallStmt { call }`, `Return { value }` (`value` nil for a bare
    `return`), `Pass`, `Break`, `Continue`, `If { condition, body, else_body }`,
    `While { condition, body }`. Bodies are lists of statements.
  - Expressions: `Int { value }`, `String { value }`, `Bool { value }`, `None`,
    `Name { name }`, `Call { name, args }`, `Unary { op, operand }`,
    `Binary { op, left, right }`. Parentheses leave no node.
- **`elif`.** `if a: ... elif b: ... else: ...` becomes
  `If(a, body, { If(b, body, else_body) })`. The inner `If` takes the `elif`
  span. Lowering needs this nesting anyway, since an `elif` condition's
  temporaries belong inside the outer `else`. The checker's join and transfer
  rules give the same answers on the nested form.
- **Spans.** A node's span is the span of the token that identifies it:
  - the name for `Function`, `Param`, `Assign`, `Name`, and `Call`;
  - the keyword for `Return`, `Pass`, `Break`, `Continue`, `If`, and `While`;
  - the operator for `Unary` and `Binary`, so a failing `+` in `a + b + c` points
    at that `+`;
  - the literal or type token for literals and `Type`;
  - the call's span for `CallStmt`;
  - `span.new(1, 1, 1, 0)` for `Program`.
- **Grammar.** One function per level, lowest precedence first:
  - `or_expr := and_expr ('or' and_expr)*`
  - `and_expr := not_expr ('and' not_expr)*`
  - `not_expr := 'not' not_expr | comparison`
  - `comparison := sum (compare_op sum)?`, where `compare_op` is one of
    `== != < <= > >=`
  - `sum := product (('+' | '-') product)*`
  - `product := unary ('*' unary)*`
  - `unary := ('+' | '-') unary | primary`
  - `primary := INT | STRING | True | False | None | NAME | NAME '(' args ')' |
    '(' or_expr ')'`
  Loops build left-associative trees. A comparison operand is a `sum`, so
  `a == not b` fails in `primary`.
- **Statements.** A statement starting with `if`, `while`, `return`, `pass`,
  `break`, or `continue` is parsed by keyword. `def` raises
  `nested functions are not supported`. Otherwise the parser reads an expression
  and looks at the next token:
  - `=`: the expression must be a `Name` (`cannot assign to this expression`).
    After the value, another `=` raises `chained assignment is not supported`.
  - `:` after a `Name`: an annotated assignment. A missing `=` after the type
    raises `annotated assignment needs an initializer`.
  - `,` after a `Name`: `destructuring assignment is not supported`.
  - Otherwise the expression must be a `Call`
    (`only calls can be used as statements`, at the expression's span).
  Simple statements then expect `NEWLINE`.
- **Blocks.** `block := ':' NEWLINE INDENT statement+ DEDENT`. The lexer only
  emits `INDENT` before a line with tokens, so a block that parses has at least
  one statement. A one-line block fails at the missing `NEWLINE`; an empty block
  fails at the missing `INDENT`.
- **File scope.** Only `def` until `EOF`. Any other token raises
  `only function definitions are allowed at file scope`. The unsupported-word
  rule below takes priority.
- **Calls.** After any `primary`, a following `(` raises
  `call target must be a function name`. This rejects `(f)(x)`, `f(x)(y)`, and
  `1(2)`. Parameter and argument lists allow one trailing comma.
- **Comparison chains.** After a comparison, another `compare_op` raises
  `comparison chains are not supported` at the second operator.
- **Unexpected tokens.** One helper raises every other syntax error.
  - A token whose kind is a reserved word without a supported construct (`as
    assert async await case class del except finally for from global import in
    is lambda match nonlocal raise try type with yield`) raises
    `'<word>' is not supported`.
  - Anything else raises `expected <what>, found <token>`. `<token>` is
    `end of line`, `end of file`, `indent`, `dedent`, `integer`, `string`,
    `'<name>'` for a `NAME`, and `'<kind>'` otherwise.

## Test plan

`tests/unit/parser_test.lua` parses `lexer.lex` output. Helpers:

- `eq`.
- `parse_error(source)` returns `"line:col: message"` and fails the test if
  parsing succeeds or raises a non-diagnostic.
- `show(node)` prints a tree compactly:
  - binary and unary operations fully parenthesized (`((a + b) * (- c))`);
  - calls as `f(a, b)`;
  - statements joined by `; ` with blocks in braces.
- `expr(text)` parses `def main() -> None:\n    x = <text>\n` and shows the
  assigned value.

Tests:

- `function_signatures`: no parameters, several with a trailing comma, each
  annotation type, and the function, parameter, and type spans.
- `annotations_required_and_limited`: a missing parameter annotation, a missing
  return annotation, and a `NAME` such as `list` in type position.
- `file_scope_holds_only_def`: an assignment at file scope, `class` and `import`
  at file scope, and an indented first line.
- `statements`: one body with each statement kind, including an annotated
  assignment and both forms of `return`.
- `if_elif_else_nests`: `if`/`elif`/`elif`/`else` nests as described, with the
  `elif` span on the inner `If`.
- `blocks_need_a_statement`: a one-line block and a block with no indented line.
- `non_call_expression_statements_rejected`: `x + 1`, `x`, and `f() == 1`.
- `assignment_forms_rejected`: chained, destructuring, augmented (the lexer's
  error), walrus (the lexer's error), an annotation without an initializer, and
  assignment to a call.
- `precedence`: `a or b and not c == d + e * -f`, left associativity of `-`,
  `and`, and `or`, `not a == b`, and `-a * b`.
- `binary_span_is_the_operator`: the second `+` in `a + b + c`.
- `not_needs_parentheses_after_comparison`: `a == not b` fails;
  `a == (not b)` parses.
- `comparison_chains_rejected`: `0 <= x < 10` and `a == b == c`, at the second
  operator.
- `call_targets_are_names`: `(f)(x)` and `f(x)(y)` fail; `f(1, g(2),)` parses.
- `multiline_expressions`: a call whose arguments span lines and a
  parenthesized expression across lines.
- `unsupported_reserved_words`: `for` and `try` statements, `lambda` and `is`
  in expressions, `in` where `:` is expected, and a nested `def`.
