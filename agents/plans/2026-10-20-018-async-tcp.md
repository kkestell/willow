# Async TCP

## Goal

Implement the `aio` TCP surface from §14: `aio.connect`, `aio.listen`, and the
`aio.Connection` and `aio.Listener` native types, whose `recv`, `sendall`, and
`accept` return coroutines that wait by suspending their task. `net`'s
semantics carry over: the same validation, messages, timeouts, and unusable
state, one unfinished operation per direction, and closing a handle waking its
pending operations.

## Related code

- `compiler/stdlib.lua`: the `aio` module, `aio.sleep` as a coroutine helper,
  and `net`'s native types to copy.
- `runtime/aio.lua`: the scheduler, `__wlo_aio_wait_fd`, `__wlo_aio_checkpoint`,
  and `__wlo_aio_wake_fd`.
- `runtime/aio_net.lua`: the async TCP handles added here.
- `runtime/host.lua`: `__wlo_socket_*`, the blocking bodies from
  `agents/plans/2026-10-20-012-tcp-wait-hook.md`, which take the wait function.
- `compiler/runtime.lua`: which runtime files a program carries.
- `tests/programs/aio_sockets.wlo`, `tests/unit/aio_test.lua`.

## Decisions

- The async helpers live in `runtime/aio_net.lua`, and call host.lua's socket
  bodies through `__wlo_runtime.socket_*` with a wait that suspends. They call
  the scheduler through `__wlo_runtime.aio_checkpoint`, `aio_wait_fd`, and
  `aio_wake_fd`, so `runtime/aio.lua` declares those without `local`.
  `compiler/runtime.lua` registers `aio_net` with `needs` on both `aio` and
  `host`, so a program using only `aio.sleep` or task groups does not carry
  host.lua.
- Each operation is a coroutine created at the call, like `aio.sleep`: the body
  checks for a request, records the direction as unfinished, runs the shared
  body, and clears the record on every departure. A second operation in a busy
  direction raises `RuntimeError` with `recv is already in progress`,
  `sendall is already in progress`, or `accept is already in progress` before
  any I/O. `recv` and `sendall` use separate records, so they run together.
- The wait each body gets wraps `__wlo_aio_wait_fd`, which is a checkpoint, and
  then checks the handle's `closed` flag, raising `ValueError` with the closed
  handle's message. Thus `close` needs only to wake the waiters; it records
  nothing per operation.
- `close` wakes the tasks waiting on its descriptor with
  `__wlo_aio_wake_fd`, a small function in `runtime/aio.lua` that scans the
  scheduler's descriptor waits and wakes with their own wait ids, so stale
  wakes are ignored as elsewhere. It runs only for a handle that was open, so a
  reused descriptor cannot be woken through a closed handle.
- `connect` and `accept` get the tag of `aio.Connection`, and `listen` the tag
  of `aio.Listener`, so protocol dispatch and diagnostics see the declared
  types. `listen`, `local_port`, `close`, `enter`, and `exit` otherwise call
  the `net` helpers.
- A wait may raise, so the shared bodies' cleanup matters: `connect` closes an
  in-progress descriptor, and a `sendall` that may have sent part of its data
  marks the connection unusable. That cleanup was the second commit of
  `agents/plans/2026-10-20-012-tcp-wait-hook.md`, which main did not take; it is
  carried here, since this slice depends on it.
- `recv` and `sendall` run together, and closing a handle wakes its waiters, so
  the same behavior has both a program test that uses task groups and unit
  tests against the runtime.

## Test plan

- `tests/programs/aio_sockets.wlo`: the §14 echo example as written, with a
  task group; a second concurrent `recv` refused while the first completes;
  `close` from another task waking a pending `recv`; and the timeouts,
  validation, end of stream, and closed handles from before.
- `tests/unit/aio_test.lua`: one operation per direction, a second `recv` and a
  second `sendall` refused, `recv` and `sendall` together, closing waking a
  pending `recv` and a pending `accept`, a cancelled partial `sendall` making
  the connection unusable, and a cancelled `connect` closing its socket.
- `make test`.

## Implementation plan

1. Declare `aio.connect`, `aio.listen`, `aio.Connection`, and `aio.Listener` in
   `compiler/stdlib.lua`.
2. Add the operation coroutines, the wait wrapper, close waking, and the
   handle conversions to `runtime/aio_net.lua`; export the scheduler hooks it
   calls from `runtime/aio.lua`, and carry the raising-wait cleanup in
   `runtime/host.lua`.
3. Add the `needs` edge in `compiler/runtime.lua`.
4. Add the program and unit tests; check off the slice in `agents/todo.md`.
