## Summary

`aio.connect`, `aio.listen`, `aio.Connection`, and `aio.Listener` are
implemented in `runtime/aio_net.lua`. `recv`, `sendall`, and `accept` return
coroutines that check for a request, record their direction as unfinished, and
run host.lua's socket bodies through a wait that suspends the task and checks
the closed flag after every wake. A second operation in a busy direction is
refused before any I/O, while `recv` and `sendall` run together. `close` wakes
the handle's waiters through the scheduler's wait ids, so they raise the
closed-handle `ValueError`. `connect` and `accept` tag their connections
`aio.Connection`, and `listen` its listener `aio.Listener`.

`compiler/runtime.lua` registers `aio_net` with `needs` on `runtime/aio` and
`runtime/host`, so an `aio` TCP program carries both, while a program using
only `aio.sleep` or task groups carries neither host.lua nor these helpers.
`runtime/aio.lua` declares `__wlo_aio_checkpoint` and `__wlo_aio_wake_fd`
without `local`, since `aio_net` calls them through `__wlo_runtime`.
`runtime/host.lua` also regains the raising-wait cleanup from the second commit
of the TCP wait hook, which main did not take: `connect` closes an in-progress
descriptor and a partial `sendall` marks the connection unusable when the wait
raises.
