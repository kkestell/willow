# Sort keys

## Plan

`agents/plans/2026-10-20-007-sort-keys.md`

## Summary

`sorted` and `list.sort` take a keyword-only `key` returning an orderable value,
for elements of any type. Keys are evaluated once each in input order, a key
that changes the list being sorted raises `list changed during sort`, and key
failures, NaN keys, and that error leave the list unreordered. `report.wlo`
orders levels by a count-then-name key, and the Rosetta Code "Sort using a
custom comparator" example is added. The plan's goal is met, and the sorting
milestone is complete.

## Departures from the plan

- A key that is not a function reports "a sort key must be a function,
  received T" instead of the generic expected-callable message, which would
  have named a `None` result.
- The earlier tests for a third positional `sorted` argument and a second
  positional `sort` argument now expect the keyword-only `key` error.

## Decisions

- The in-place change check treats a NaN element that is still NaN as
  unchanged.
