# Exceptions review

## Scope and coverage

Reviewed the staged implementation of `agents/plans/2026-10-15-007-exceptions.md`
against willow.md §19: `compiler/parser.lua`, `compiler/bind.lua`,
`compiler/check.lua`, `compiler/lower.lua`, `compiler/emit.lua`,
`runtime/core.lua`, the new and updated tests, `examples/exceptions.wlo`, and
`agents/todo.md`. Traced generated Lua for nested `try`, bare `raise`, and
departures from protected blocks inside loops, and ran small programs for host
failures inside `try`, narrowing through `except` and `finally`, and void
returns through `finally`. Real memory exhaustion was not reproduced; that path
was confirmed from the LuaJIT source (`lj_err_mem` throws without calling the
message handler) and by feeding the reporter the raw string LuaJIT produces.

## Fixed

- **Conditional assignment in `finally` kept a stale narrowing**
  (`compiler/check.lua:513`): a local first assigned in the `try` body and
  reassigned to `None` on some paths through `finally` kept its narrowed type
  after the `try`, so `print(y + 1)` checked and then failed at run time with a
  raw Lua arithmetic error. The local is missing from the `finally` exit state
  because it was not definite at `finally` entry, so the join never saw it. Now
  every local the `finally` clause assigns falls back to its declared type
  before the `finally` exit state is applied. Added a regression case to
  `try_flow` in `tests/unit/check_test.lua`.
- **Memory exhaustion crashed the reporter** (`runtime/core.lua:534`): LuaJIT
  does not call the `xpcall` message handler for memory errors, so `__wlo_run`
  passed the raw string `"not enough memory"` to `__wlo_report`, which indexed a
  nil location and died with a Lua traceback instead of the §10 report. The same
  happened when such an error was re-raised from `__wlo_try` with no mapped
  frame left on the stack. `__wlo_report` now wraps a raw string through
  `__wlo_catch` and omits the location prefix when no Willow frame survives
  (`error: not enough memory`).
- **Stale error representation in the spec** (`willow.md:556`): §10 still said
  errors carry `category`; the runtime now records the class, message,
  location, and frames. The sentence names the message, location, and frames.

## Findings

No open findings.

## Checks run

- `make test`: 171 passed, 0 failed, before and after the fixes.
- Ad hoc programs run through `./willow run`: stack overflow inside
  `try`/`except Exception`/`finally` terminates without running either clause;
  `continue`, `break`, and void `return` through `finally`; bare `raise` in a
  nested `try` inside a handler; `Exception | None` narrowed after an `as`
  assignment; the conditional-`finally` case (now a type error).
- `__wlo_report("not enough memory")` in a built program: printed a Lua
  traceback before the fix, `error: not enough memory` after.

## Verdict

The implementation follows the plan and §19. Two bugs and one stale spec
sentence were fixed; nothing remains open.
