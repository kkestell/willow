# Compiler review

## Scope and coverage

Reviewed all 15 Lua files in `compiler/`, including lexing, parsing, binding,
types, checking, lowering, emission, runtime assembly, module loading, manifests,
the CLI, and the test runner. Traced their behavior against `docs/spec.md`,
relevant runtime helpers, and existing unit and program tests. The working tree
was clean before review. No compiler or runtime code was changed.

Gaps:

- Execution checks ran on macOS only; Linux ABI behavior was not exercised.
- Runtime files were inspected where needed to trace compiler behavior, not
  reviewed in full as an additional scope.
- Focused reproductions exercised the CLI's run, check, and test paths. Each
  reproduction was not separately repeated through standalone executable builds.

## F1. Standard-library combinations exceed Lua's local limit

High · Correctness · Needs plan · `compiler/runtime.lua:24`

Every selected optional runtime declares all its exported helpers as locals in
the generated chunk's outer scope. The blocks hide internal locals but leave
these exports live alongside the core helpers. Combining supported library
features exceeds LuaJIT's 200-local limit even with just one user function.
Valid source passes type checking but cannot run, compile, or build because
`cli.translate` loads the generated chunk before delivering it.

### Evidence

Running this program fails while loading generated Lua with
`main function has more than 200 local variables`:

```python
import fs
import io
import cli
import http

def main() -> None:
    if False:
        print(fs.exists("."))
        print(io.stdin().readline())
        print(cli.parser("x").help())
        print(http.urlencode({"x": "y"}))
        print(bytes([1]).decode())
        print("x".upper())
```

The branch avoids performing any I/O; merely generating the required helpers
triggers the failure. This does not depend on a large user function or an
unusually large number of user declarations.

### Fix

Plan how runtime exports are represented and scoped so ordinary combinations do
not accumulate hundreds of outer locals. A runtime helper table is one possible
approach. This needs coordinated changes to runtime assembly, generated helper
references, and helper-to-helper references, with checks for combined libraries
and readable generated Lua. Raising a diagnostic for this small valid program
would not restore the required behavior.

## F2. Qualified entry-module calls can call a local variable

Medium · Correctness · Trivial · `compiler/emit.lua:105`

The binder correctly resolves an explicitly qualified call to the entry module,
but the emitter uses the bare function name whenever caller and callee are both
in that module. A local with the callee's name then captures the generated call.
Self-imports also do not cause an entry-module function table to be created.
The specification permits importing the entry module and states that locals
hide their own names, not unrelated module-qualified members.

### Evidence

Save the following as `self_call.wlo`:

```python
import self_call

def f() -> int:
    return 7

def main() -> None:
    f = 1
    print(self_call.f())
```

`willow run self_call.wlo` accepts the source and then reports
`attempt to call local 'f' (a number value)` instead of printing `7`.

### Fix

Preserve whether a user function call is qualified when lowering a `Call`.
For a qualified call, emit the target module table reference even when both
modules are the entry module. Count self-imports when setting `entry_imported`
so the existing table declaration and population code also runs for them.
Keep bare references for unqualified calls and entry function definitions.

## F3. Negative-zero defaults lose their sign

Medium · Correctness · Trivial · `compiler/emit.lua:53`

The parser folds a signed default literal into its numeric value. The emitter
then formats every integral value in range using `%d`, turning negative floating
zero into `0`. This changes parameter and record-field defaults despite the
specification preserving the distinction between `-0.0` and `0.0`.

### Evidence

```python
def f(x: float = -0.0) -> None:
    print(x)

class R:
    x: float = -0.0

def main() -> None:
    f()
    print(R().x)
    print(-0.0)
```

Observed output is `0.0`, `0.0`, and `-0.0`. All three values should print as
`-0.0`.

### Fix

Before the integer-formatting branch in `number`, return the Lua literal
`-0.0` when `value == 0 and 1 / value < 0`. This preserves folded floating
negative zero without changing integer zero.

## F4. Membership rejects lists of bytes

Medium · Correctness · Trivial · `compiler/check.lua:424`

List membership requires printable operand and element types, although the
specification requires types that support equality. Bytes support equality but
are not printable. Consequently, valid membership checks on `list[bytes]`, and
comparable unions containing bytes, are rejected. The runtime list-membership
helper already uses `__wlo_equal`, which compares byte contents.

### Evidence

```python
def main() -> None:
    data = bytes([1])
    print(data in [data])
```

The compiler reports `operator 'in' cannot be applied to bytes and list[bytes]`
instead of accepting the program and printing `True`.

### Fix

Replace `types.printable(left)` and `types.printable(item)` in the membership
branch with `types.comparable(left)` and `types.comparable(item)`. Retain the
assignability check and the special string-substring rule. This also fixes
`not in` through the same branch.

## F5. A function named io makes passing tests fail

Medium · Correctness · Trivial · `compiler/emit.lua:389`

The generated test footer uses the Lua global `io` after declaring entry-module
functions as locals. A legal Willow function named `io` shadows that global.
The test body returns normally, but creating its completion marker then fails,
so the runner reports a failed test.

### Evidence

```python
def io() -> None:
    pass

def test_ok() -> None:
    pass
```

`willow test` reports `attempt to index local 'io' (a function value)` followed
by `test did not return (exit status 1)` and `0 passed, 1 failed`.

### Fix

For test chunks, capture Lua's `io.open` in a reserved internal local before
declaring user functions, and use that local in the completion-marker footer.
The internal name must follow the existing `__wlo_` naming convention so user
identifiers are mangled away from it.

## F6. False and null manifests crash the CLI

Medium · Error handling · Trivial · `compiler/manifest.lua:45`

The JSON parser successfully returns Lua `false` or `nil` for JSON `false` or
`null`. `manifest.read` mistakes either for a parse failure and concatenates an
absent error message. It crashes outside the CLI's diagnostic handling instead
of reporting that the manifest must be an object.

### Evidence

Running `willow check` with a `willow.json` containing either `false` or `null`
reports `manifest.lua:46: attempt to concatenate local 'err' (a nil value)` and
a Lua stack trace. A manifest containing `true` correctly reports
`error: willow.json: expected an object`.

### Fix

Test `if err then` after `parse_json(text)` instead of `if not data then`.
Successful false/null values will then reach the existing object-type check,
while actual parser errors retain their messages.

## F7. Root-directory paths become the current directory

Medium · Correctness · Trivial · `compiler/manifest.lua:25`

`under` removes every trailing slash, including the only slash in `/`, and
`prefix` interprets the resulting empty string as the manifest directory.
The manifest explicitly supports absolute `source`, `dependencies`, and `tests`
paths, but `/` silently selects a different directory. This can compile the wrong
entry file or search the wrong modules and tests.

### Evidence

In a temporary directory containing a valid local `main.wlo` and
`willow.json` with `{"source":"/"}`, `willow check` succeeds by reading the
local file. The requested entry is `/main.wlo`, which does not exist.
The same normalization functions process dependency and test roots.

### Fix

Have `under` preserve `/` for paths consisting entirely of slashes, while
retaining the empty result for `.`. Have `prefix` return `/` directly when
`under` returns `/`, so it adds no extra slash. The existing test-path assembly
can then preserve the root directory too.

## F8. Unreadable manifests are treated as absent

Medium · Error handling · Trivial · `compiler/manifest.lua:38`

`manifest.read` returns the absent-manifest result for every file-open error
code, not just a missing file. An existing manifest that cannot be read is
therefore ignored. Ordinary commands misleadingly report that no manifest
exists; `willow test` can instead proceed with file-mode roots and discovery,
without applying the project's configuration.

### Evidence

Created a temporary `willow.json` containing `{}`, removed its read permissions,
and ran `willow check`. It reported
`no source file given and no willow.json in the current directory` rather than
the permission failure. Permissions were restored after the check.

### Fix

Return `nil` only when the loader's error code is `ENOENT` (`2`), matching the
loader's existing convention. Let every other unsuccessful read reach
`return false, err`, which the CLI already reports as a broken manifest.

## Verdict

Eight confirmed findings: one High and seven Medium. F2–F8 are trivial fixes;
F1 needs an implementation plan. The existing suite passes but does not cover
these cases. Leave the review staged and do not commit until the findings are
addressed.
