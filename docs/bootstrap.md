# Bootstrapping Willow

Willow builds its native compiler from source without an existing Willow
executable. A small C compiler builds a compiler written in Willow, which
then builds the compiler in [`compiler/`](../compiler/).

See the [README](../README.md#setup) for host requirements and setup. Run the
commands below from the repository root.

## Compiler stages

| Stage | Source | Written in | Executable |
| --- | --- | --- | --- |
| 0 | [`bootstrap/stage0/`](../bootstrap/stage0/) | C11 | `build/stage0/willow0` |
| 1 | [`bootstrap/stage1/`](../bootstrap/stage1/) | L0, a subset of Willow | `build/willow1` |
| 2 | [`compiler/`](../compiler/) | Willow | `build/willow2a`, then `build/willow2b` |

The [Makefile](../Makefile) builds the chain in this order:

1. The host C compiler builds `willow0`.
2. `willow0` builds the stage 1 sources into `willow1`.
3. `willow1` builds the stage 2 sources into `willow2a`.
4. `willow2a` builds the same stage 2 sources into `willow2b`.
5. `willow2b` is copied to `build/willow`, the compiler used by normal builds
   and tests.

L0 is the subset of the current language that stage 0 supports. Stage 1 and
the core runtime stay within that subset. Stage 1 supports the constructs
needed to compile stage 2; stage 2 implements the language described in the
[specification](spec.md).

Each stage emits QBE intermediate language (IL). For a native build, QBE
turns that IL into assembly, and `cc` assembles and links it with libgc and
the math library. Stages 0 and 1 expose the small command interface needed
by the bootstrap:

```sh
build/stage0/willow0 compile program.wlo -o program.ssa
build/stage0/willow0 build program.wlo -o program
build/willow1 compile program.wlo -o program.ssa
build/willow1 build program.wlo -o program
```

## Core and embedded sources

[`bootstrap/core/core.wlo`](../bootstrap/core/core.wlo) is the shared runtime,
written in L0 over low-level intrinsics and foreign calls. Its source is
compiled into each program. The [core API](../bootstrap/core/API.md)
documents the runtime functions stage 0 calls and the intrinsic layer.

Stage 0 embeds the core source as a C string, generated by Make into
`build/stage0/core.inc`.

For stages 1 and 2, [`bootstrap/prepare.sh`](../bootstrap/prepare.sh) copies
the compiler's `.wlo` files into `build/stage1/` or `build/stage2/` and
generates two modules:

- `core_source.wlo` holds the text of `bootstrap/core/core.wlo`.
- `lib_source.wlo` holds the text of the modules in [`lib/`](../lib/),
  indexed by module name.

The compiler loaders use these embedded sources when compiling programs.
The compiler therefore carries its runtime and standard library sources
with it. Edit the originals; the prepared files under `build/` are generated
and replaced during rebuilding.

## Builds and fixed-point checks

```sh
make                 # Build build/willow through the complete chain.
make bootstrap       # Also check the stage 2 fixed point.
make bootstrap-test  # Run the bootstrap checks and the normal test suite.
```

`make` builds the self-compiled executable. `make bootstrap` additionally
asks both `willow2a` and `willow2b` to compile
`build/stage2/willow.wlo`. It writes their IL to `build/stage2a.ssa` and
`build/stage2b.ssa` and compares those files with `cmp`. Identical output
establishes a fixed point for compiling the compiler's own source.

`make bootstrap-test` runs that comparison and then:

- Builds and runs the L0 programs and core tests with stage 0.
- Runs stage 1's lexer, parser, type, and binder tests, then checks stage 1's
  own self-compilation fixed point.
- Runs stage 2's unit tests, compiler drivers, and program and runtime tests,
  including a self-compilation fixed-point check with test library modules
  embedded.
- Runs `make test`, which exercises `build/willow` with the conformance
  programs, module cases, and command tests.

The stage-specific checks live in
[`bootstrap/tests/stage1.sh`](../bootstrap/tests/stage1.sh) and
[`bootstrap/tests/stage2.sh`](../bootstrap/tests/stage2.sh).
